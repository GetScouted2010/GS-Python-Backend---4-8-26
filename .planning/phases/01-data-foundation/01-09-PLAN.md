    Logic:
    1. Run the five commands IN ORDER via `django.core.management.call_command`, passing the forwarded options: import_clubs_playstyles -> import_players -> import_position_roles -> import_compatibility_scores (unless --skip-compatibility) -> import_transfers. Print a clear banner before each step.
    2. After all steps, build a reconciliation dict comparing live table counts to source CSV row counts:
       - Club.objects.count() vs distinct clubs derived; Player.objects.count() vs Players.csv data-row count; Transfer.objects.count() vs transferdata data-row count; PlayerRoleScore + PlayerClubCompatibility totals (report actual, no fixed expectation since they depend on file overlap).
       - Compute the source CSV row counts by reading each file's line count (minus header) — do not hardcode; read from the actual files under DATASET_DIR.
       - Flag any table whose count differs from its source expectation in a `reconciliation` report section with `{table, source_rows, db_rows, delta}`.
    3. Write ONE combined report (JSON + Markdown) via ImportReport.add_section for each sub-report + the reconciliation. Print the combined report path and a one-line PASS/REVIEW summary (REVIEW if any reconciliation delta is unexpected).

    docs/IMPORT_RUNBOOK.md: document (a) prerequisites (Postgres up, DATABASE_URL set, `pip install -r requirements/dev.txt`, `python manage.py migrate`); (b) the single command `python manage.py import_all`; (c) the dependency order and why; (d) how to read the report (where it lands, what the reconciliation + field_issues + unresolved_club_names sections mean, and the EXPECTED non-bugs, each with its cause so a reviewer does not mistake them for silent data loss):
       - ~77% of clubs have null Club.playing_style (only ~239/1,059 clubs appear in Playstyles.csv).
       - ~3,081 GK players have zero PlayerRoleScore rows (there is no GK Positions file — GK role scores don't exist upstream).
       - ~18% Contract_expires + ~14% Market_value missing on Player (source blanks, kept as null and flagged, never skipped).
       - INTENTIONAL BOUNDED EXCEPTION to the "never skip a row" policy: `import_position_roles` and `import_compatibility_scores` SKIP (do not insert) any score row whose player UniqueID does not match an existing Player, because `PlayerRoleScore.player` / `PlayerClubCompatibility.player` are NON-NULLABLE FKs (a null-FK row is structurally impossible, unlike Transfer.player which is nullable). This is logged per skipped UniqueID in each command's report (`UniqueID -> no_matching_player`) and is bounded to ~0 occurrences in practice (RESEARCH.md verified ~100% UniqueID overlap between Players.csv and the role/compatibility files). Reviewers should confirm this count is ~0; a non-trivial count means the upstream Player import was incomplete, not silent data loss here.
       - (e) the note that it is safe to re-run (idempotent).
