  <action>
    Create players/ai/grounding.py implementing the four pure functions from 10-RESEARCH.md Pattern 5 (no existing formatter exists anywhere in the codebase — grep-confirmed — so build from scratch with stdlib `re`):
    - `NUMERIC_TOKEN_RE` compiled regex (VERBOSE|IGNORECASE) matching an optional currency symbol, `(?P<num>\d[\d,]*(?:\.\d+)?)`, and an optional `(?P<suffix>million|mil|m\b|thousand|k\b|%|percent)`.
    - `_normalize(num_str, suffix) -> float`: strip commas, float(); suffix in {million,mil,m} => *1_000_000; {thousand,k} => *1_000; else pass through.
    - `extract_numeric_tokens(text) -> list[float]`: normalize every regex match.
    - `flatten_grounding_values(grounding) -> list[float]`: recursive walk collecting int/float leaves ONLY, explicitly excluding bool (`isinstance(node, (int,float)) and not isinstance(node, bool)`), recursing into dict values and list/tuple items, skipping str/None.
    - `is_grounded(value, grounding_values, rel_tol=0.05, abs_tol=0.5) -> bool`: build candidate set `{value, value/100, value*100}`; return True if any candidate is within `max(abs_tol, rel_tol*max(abs(gv),1))` of any grounding value.
    - `validate_grounding(narrative_text, grounding) -> list[float]`: return the list of extracted tokens that fail is_grounded against flatten_grounding_values(grounding). Empty list == fully grounded.
    Make rel_tol/abs_tol module-level default constants that are easy to adjust (they will be empirically tuned against real LLM output during Plan 03/04 manual verification).

    Create players/tests/test_ai_grounding.py covering ALL Behavior cases above — critically BOTH an accept-tolerant-number test AND a reject-hallucinated-number test (10-VALIDATION.md requires both paths proven).
