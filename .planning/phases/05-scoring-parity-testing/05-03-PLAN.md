<critical_corrections>
1. TFM SCALE: `get_financial_fit(...)["predicted_fee"]` is MONEY-scale (the service applies np.expm1 internally).
   The oracle `tfm` column is LOG-scale (13-17). To compare, use the shared `compare_tfm_series`/a scalar
   money-scale comparison: convert the oracle value to money via `np.expm1(oracle_tfm)` and compare to
   `predicted_fee` with rel tol 0.1%. NEVER compare the money-scale predicted_fee directly against the
   raw log-scale oracle column.
2. GK/LB/RB have ZERO non-null cs/transfer_probability in the real data. The sampler MUST NOT require a
   non-null CS example from those groups (it will never find one) — instead sample them specifically to
   assert correct null propagation. Zero-minutes / age=0 players are extremely rare (1 / 22 respectively) —
   do not build the sampler to require many of them (that is Plan 04's edge-case concern, not this file's).
3. PLAYER_ID DTYPE (blocker fix): `pid` originates from a `Player` queryset (`.id`, a `uuid.UUID`), but the
   oracle DataFrame from `load_oracle_df()` is indexed by STRING player_id. `oracle.loc[pid, ...]` with a
   raw UUID key against a string index raises `KeyError`. You MUST wrap EVERY oracle lookup as
   `oracle.loc[str(pid), ...]` (or normalize the sample to store `player_id` as `str` at build time). Plan 04
   already uses `oracle.loc[str(pid)]` for the identical operation — mirror that here in BOTH tasks.
</critical_corrections>
