<objective>
Denormalize the four final "own-club" scores onto the Player model as nullable, indexed FloatFields so list/browse/sort endpoints (Phase 7 CRUD-01) can query score thresholds as O(1) plain-column queries with no scoring math in the request cycle. Then protect the existing scoring pipeline from the name collision these 4 new fields introduce: `build_players_df()` dynamically enumerates every Player field, so the new `compatibility_score` field would silently leak into the reconstructed DataFrame and corrupt the `cs_tp[["compatibility_score",...]].merge(on="player_id")` step that oracle generation, TFM training, and the live Financial Fit endpoint all depend on.

Purpose: Success Criterion 3 — "Final scores are denormalized onto model fields so list/browse/sort endpoints never invoke scoring math directly." This is the foundation the recompute command (Plan 03) writes into and the timing test (Plan 04) reads from. The reconstruct fix keeps the already-proven scoring pipeline correct once these output fields exist on the model.
Output: 4 new Player fields + their indexes + the applied migration + a hardened build_players_df() that excludes the 4 output fields + a regression test proving no leak and clean merges.
</objective>
