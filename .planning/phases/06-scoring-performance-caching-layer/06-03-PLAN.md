   - compatibility_score        = cs_tp["compatibility_score"]  (index is player_id)
   - financial_fit_score        = financial_money  (index is player_id)
   - transfer_probability_score = cs_tp["transfer_probability"]
   Coerce every value with `None if pd.isna(v) else float(v)` so pandas NaN becomes a real SQL NULL (never 0 — the "never zero-fill" invariant; GK/LB/RB CS/TP legitimately stay NULL).

5. Write via bulk_update inside a transaction:
   - Build lightweight `Player(id=pid, impact_score=..., compatibility_score=..., financial_fit_score=..., transfer_probability_score=...)` instances (constructing an in-memory Player with only pk + the 4 fields set is sufficient for bulk_update, which issues UPDATE ... WHERE id=pk — this avoids loading 41,708 full rows into memory).
   - `with transaction.atomic(): Player.objects.bulk_update(objs, ["impact_score","compatibility_score","financial_fit_score","transfer_probability_score"], batch_size=1000)`. The atomic wrapper guarantees a live request reads the OLD denormalized values until the whole update commits — no partial-write window (the safe-write requirement in 06-CONTEXT.md).
   - batch_size=1000 keeps each UPDATE payload reasonable for Postgres across 4 columns × 41,708 rows (bulk_update is the established Phase-1 write pattern).

6. Call `clear_scoring_caches()` AGAIN at the end so the next live request rebuilds the in-process aggregate against the just-refreshed data.

7. `self.stdout.write(self.style.SUCCESS(...))` reporting: total players updated, and per-field non-null counts (e.g. "impact_score: 41707 non-null, compatibility_score: 39xxx non-null (GK/LB/RB null by design)") so the operator can eyeball that null-propagation happened rather than silent zero-fill.

Add a `--batch-size` argument (default 1000) via add_arguments for tuning. Add a module docstring explaining this is the SCORE-07 rebuild trigger, follows the explicit-management-command convention (NOT signals, which bulk_create/bulk_update never fire), and reuses generate_scoring_oracle.py's proven orchestration writing to Player fields instead of a CSV.
